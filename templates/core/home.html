Overview

The application implements a normalized relational schema (core.models.CustomerRecord) focused on ACID-compliant transactions for single-request consistency. It uses Django's ORM for expressive query construction while allowing raw SQL when necessary for optimisation.

Feature Summary
  • CRUD operations with server-side validation and CSRF protection.
  • Passbook generation endpoints with paginated transaction history.
  • Template-based UI for quick prototyping and accessible components.
Performance Metrics
  • Latency (p95): aim for < 200ms on local dev for simple queries.
  • Throughput: use load tools (wrk, k6) to measure RPS.
  • N+1 prevention: use select_related and prefetch_related.
terminal
Developer Notes
  • Env: .env is loaded by python-dotenv in settings.
  • DB: Set DUMMY_DATABASE=true for local SQLite or false for MySQL.
  • Migrations: python3 manage.py makemigrations && migrate.
  • Dev server: python3 manage.py runserver.
Scaling Thoughts

Add caching (Redis) for read-heavy endpoints, introduce connection pooling, and move long jobs to Celery workers for async processing at scale.
